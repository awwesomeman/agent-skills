# TASKS.local.md 模板

把下方區塊複製到 repo 根目錄的 `TASKS.local.md`，並把該檔加入 `.gitignore`。
標題可依專案 `AGENTS.md` 指定的語言翻譯；章節編號保持不變。

```markdown
# 任務清單（本機，不 commit）

你和 agent 共用的進度表，兩邊都可以直接改；agent 改之前會先重讀。溝通時用編號（例如「3.2」）。
重要、要追蹤的事在 GitHub issue，這裡只放總表與次要事項。回報給你之後才從原章節移除。
最後更新：YYYY-MM-DD HH:MM（<時區>）。

## 1. 總覽

## 2. 進行中
| # | 項目 | 狀態 |
|---|------|------|

## 3. 等你決定
| # | 項目 | 狀態 |
|---|------|------|

## 4. 等你處理
| # | 項目 | 狀態 |
|---|------|------|

## 5. 可以做（依序）
| # | 項目 | 狀態 |
|---|------|------|

## 6. 之後再看
| # | 項目 | 狀態 |
|---|------|------|

## 7. 擱置（有 issue，不主動做）

## 8. <各 repo 自訂章節>

## 9. 近期完成
| # | 日期 | 項目（原編號） | 結果 |
|---|------|----------------|------|
```

## 週期同步提示詞

長 session 中當作週期提醒的提示詞：

> 任務清單同步（週期提醒）：重讀 TASKS.local.md，對照目前的 PR、背景子代理、待批准事項與對話裡已做的決定，逐項檢查所有章節有沒有過時內容：已解決或已完成的移到「近期完成」（寫日期與結果，連 PR / issue），超過保留期的刪掉；仍在進行的更新狀態與時間。表格保持「章節.序號」編號，新項目接在最後，不重排既有編號。程式或資料的改動要有 PR / issue，純決定不用開 issue。沒有變化就只改「最後更新」時間，不回報；有變化才用一兩句話告訴使用者改了什麼並引用編號，語言依專案 AGENTS.md 指定。
