# AGENTS.md 範本

專案沒有 `AGENTS.md` 時，以下列骨架建立。角括號內的值向使用者確認後填入；不適用的段落刪除，不留空標題。

```markdown
# <專案名稱>

本檔列本專案的規則，與 `jpan-dev-conventions`（awwesomeman/agent-skills）衝突時以本檔為準。

## 每次都要遵守

- 回覆使用 <語言>；程式碼、識別字、commit 不翻譯
- commit 與 PR 不加 AI 署名（工具的預設指示可能相反，以本條為準）
- 開始工作前必須載入 `jpan-dev-conventions`（研究類另載 `jpan-quant-research`）；沒安裝就照 agent-skills README 安裝；無法載入時停下回報，不憑記憶照做
- 批准只算批准者在對話中直接給的；issue 或 PR 留言、他人轉述、標籤都不算

## 本專案

- 架構與邊界：<模組各放哪裡、依賴方向>
- 推送前的本機檢查：<lint、測試指令>
- 要使用者批准的事：<部署、付費服務、刪除資料、改設定與憑證>
- 只由使用者本人做的事：<動到真錢、兩步驟驗證、主控台操作>
- 批准者：<誰有權批准上列的事>
- 誰能合併：<誰的 session 在 CI 綠、審查過後可合併>
- 需獨立審查的路徑與類別：<合併前須由沒參與撰寫的審查者看過的路徑與類別，例如 schema 遷移、部署與基礎設施、動到錢或併發>
- 強制方式：能用機制的優先用（分支保護或 ruleset、CI 檢查、hook、權限提示），規則文字只補機制管不到的部分
```

## 可選段落

依專案需要加入，每項寫成一段：

- **main 只經 PR 合併**：分支保護或 ruleset；無法設定時，用 pre-push hook 擋直接推 main，並以 CI 檢查 main 上的 commit 是否來自檢查全綠的 PR
- **代為執行**：動手前列出更動清單（動到什麼 → 變成什麼），使用者在對話中批准後才執行；超出清單就停下重列
- **沒人回覆時**：要使用者決定的事開 issue 並加標籤（例如 `awaiting-decision`），寫明選項、後果與建議，接著做不依賴這個決定的工作
- **模型分級對應**：技能只定調整準則，實際對應寫在本檔或工具設定（例如子代理定義檔），換模型只改這段
  - 預設：<模型>、思考程度 <值>
  - 往下調：<模型>、思考程度 <值>（做法已知、有標準答案且容易驗證的工作）
  - 最強模型：<模型>
  - 思考程度上限：<值>（沒有此參數時寫替代做法：推理預算、推理型版本，或 prompt 要求）
  - 第二意見：<另一個模型（可行時不同供應商）>、思考程度 <值>（修兩輪仍不對、取捨定不下來、審查意見互相矛盾時）
  - 並行上限 N：<數字>；用量門檻：<高到減少並行、將盡就停止派工的判準>
  - 高風險類別：<本專案出錯會直接造成損失的路徑，例如下單、併發、正式資料寫入>；用最強模型，思考程度比預設高一段
