# Claude Code 工具備註

使用 Claude Code 時適用；其他工具不需讀。與專案 `AGENTS.md` 衝突時以 `AGENTS.md` 為準。行為以官方文件為準，下列僅列要點與連結。

## 指令檔與子代理

- [AGENTS.md 載入規則](https://code.claude.com/docs/en/memory#agents-md)：有 `CLAUDE.md` 或 `CLAUDE.local.md` 時不載入 `AGENTS.md`；repo 只放 `AGENTS.md`
- [子代理啟動時載入的內容](https://code.claude.com/docs/en/sub-agents#what-loads-at-startup)：Explore、Plan 不載入專案指令檔；派它們時把規則寫進 prompt
- [子代理檔頭](https://code.claude.com/docs/en/sub-agents)：`.claude/agents/*.md` 寫 `model` 與 `effort`，作為專案的模型對應；雲端 session 在 prompt 寫明模型與 effort
- 子代理的 worktree 用 Agent 工具的 `isolation: "worktree"`（同上頁），沒有改動會自動清掉
- 遠端已刪的分支與其 worktree 用 `/clean_gone`，由 `commit-commands` plugin 提供

## 指令

[Commands](https://code.claude.com/docs/en/commands)：

- `/code-review`：審查
- `/usage`：用量

## 雲端 session

- `gh issue`、`gh pr` 會被擋（GraphQL）；改用 `gh api repos/<owner>/<repo>/...` 或內建的 GitHub 工具
- GitHub proxy 與開 PR 的內建工具會在 PR 內文加 `Generated by` 標記；開完 PR 立刻用內建的更新 PR 工具重寫內文，再讀回確認，不用 `gh api -X PATCH`
- 雲端 session 要用資料庫或本機資源時，提出改用 Work locally
- 雲端載入技能：在 claude.ai 的 Customize > Plugins 加 marketplace（[Cloud session 分頁](https://code.claude.com/docs/en/plugins/install)）

## 不加 AI 署名

settings 的 `attribution` 設為 `{"commit": "", "pr": "", "sessionUrl": false}`，工具就不再加署名與 session 連結。`attribution` 可放任何設定檔；建議 commit 在 repo 的 `.claude/settings.json`，單一 repo 的雲端 session 也會讀（[官方說明](https://code.claude.com/docs/en/settings#settings-in-cloud-sessions)）。規則文字只補機制管不到的部分。
